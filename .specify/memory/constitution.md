# 9Router-Max 项目宪法（Constitution）

## 核心价值

1. **真实优先，拒绝伪实现**：所有"已完成"必须有可执行代码、可运行命令、可复现验证。禁止把 MVP/局部实现/Mock 包装成完整落地。
2. **生产可交付**：线上已在运行的项目，一切改动必须考虑构建、部署、调用、回归、维护闭环。
3. **小白可用**：任何功能都要有清晰的入口、反馈、空态、错误态、恢复路径，不能"看起来有其实不能用"。
4. **一次调用跑通**：新增 API/功能必须让调用方按最少步骤即可调用成功，前后端契约、参数、返回、鉴权完全一致。
5. **小步闭环**：先稳定再高级；一次只改一批高相关改动，保持兼容与可回滚。

## 技术原则

### 架构
- 分层清晰：`src/app/api`（接口面）→ `src/sse`（网关 glue）→ `open-sse`（provider 无关引擎）→ `src/lib/db`（持久化 repos）。跨层需显式说明。
- 持久化统一走 `src/lib/db/repos/*` + 适配链（bun:sqlite → better-sqlite3 → node:sqlite → sql.js），新业务不得直接裸写文件。
- 新功能优先复用现有模式（repo 模式、dashboardGuard 鉴权、NO_STORE 头）。

### 代码质量
- API 路由必须：校验输入、返回稳定结构、错误信息不泄漏内部细节、设置 `no-store` 防缓存。
- DB 写入必须事务内原子；并发安全用项目既有模式（如 mutex / 事务）。
- 前端必须处理：空态、加载态、错误态、防重复提交、危险操作确认。
- 测试：核心逻辑必须有用例，跑 `tests/` 独立包（vitest），用独立临时 DB。

### 性能
- 关键 API 避免 N+1；DB 查询用索引列；流式路径不阻断。
- 网关路由、账号选择可以逐步引入数据驱动打分（价值/健康），但默认开关关闭、可回退。

### 安全
- 所有 `/api/*` 除显式白名单外默认需鉴权（JWT / CLI token）。
- 表单输入：长度上限、类型校验、XSS 防护（不渲染未清洗 HTML）。
- 敏感头不转发、错误不泄漏密钥；使用 `sanitizeSecrets` 等既有工具。

## 决策框架

做技术决策时依次考虑：
1. 是否符合核心价值（真实、闭环、可验证）？
2. 是否会影响现有生产链路？影响半径多大？
3. 是否与项目现有风格/模式一致？
4. 是否易于回滚？
5. 长期维护成本如何？

## 质量门禁（验收时必须满足）

- [ ] 构建通过（`npm run build`）
- [ ] 相关单元测试通过（`tests/` vitest 独立包）
- [ ] 关键接口 E2E 可调用（真实 HTTP）
- [ ] 前端页面空/错/加载态完整
- [ ] 文档（README/CHANGELOG/i18n）与真实行为一致
- [ ] 无未验证就宣称完成
