# 特性规格：生产加固与终局闭环审计

## 问题陈述

9router 已在生产环境部署运行。此前批次实现了「技能系统动态化」（save_skill / uses+1 / confidence 强化 / API + 前端页），但用户要求进行**终局闭环总审计**：不仅代码可跑，更要满足——调用方一次调用即通、前后端契约严格对齐、边界与异常全覆盖、UI/UX 空错态完整、文档与真实行为一致、并发/安全/兼容性无隐患。

## 用户故事

### 故事 1：API 调用方一次调用跑通

作为调用 `/api/skills` 的客户端
我想要 API 的请求/响应结构、鉴权方式、错误码在文档与实际实现之间完全一致
以便于我按 README 就能无踩坑接入。

**验收标准：**
- [ ] GET/POST `/api/skills`、GET/PUT/DELETE `/api/skills/[id]`、POST `/api/skills/[id]/use` 全部真实可用且已被 E2E 验证
- [ ] 鉴权行为与 dashboardGuard 的 deny-by-default 一致（未登录 401/重定向，登录后可访问）
- [ ] 参数校验覆盖：缺 name/content → 400 明确错误；超长字段有上限
- [ ] 错误信息不泄漏内部细节，状态码语义正确

### 故事 2：前端页面完整可用

作为仪表盘用户
我想要技能页面对空/错/加载/重复点击/删除确认有完整反馈
以便于我不用猜就能完成保存、使用、删除技能。

**验收标准：**
- [ ] 无技能时显示引导空态；加载中有提示；接口失败有可见错误
- [ ] 新建表单必填校验前后端一致；提交有 loading 防重复
- [ ] 「使用一次」即时更新 uses/confidence；删除有确认
- [ ] 与既有页面风格一致，小屏可用

### 故事 3：数据安全与并发正确

作为系统维护者
我想要技能数据在并发使用、损坏数据、超长输入下不丢、不崩、不被注入
以便于生产长期稳定。

**验收标准：**
- [ ] recordSkillUse 原子递增（事务内），并发不丢 uses
- [ ] 损坏的 kv JSON 有容错（rowToSkill 不抛）
- [ ] name/content/tags 有长度上限；内容不引入 XSS 渲染风险
- [ ] 新增数据只写入 userSkills scope，不影响既有数据（无迁移风险）

### 故事 4：文档与真实行为一致

作为新部署者/维护者
我想要 README（中文主文档）、i18n、CHANGELOG 描述与真实 API/功能一致
以便于不看源码就能正确使用和排障。

**验收标准：**
- [ ] README.md「技能系统」的 URL/方法/字段与代码一致
- [ ] i18n/README.zh-CN.md 同步；README.en.md 补充或标注
- [ ] CHANGELOG v0.5.70 描述准确

## 非功能需求

- **兼容性**：不改动既有 provider/combos/usage 逻辑；新增代码零迁移
- **稳定性**：构建、启动、E2E 全通过；并发写不丢数据
- **可维护性**：遵循 repo 模式；代码 <50 行/函数、文件 <800 行
- **安全性**：鉴权默认关闭公网；输入有界；无 XSS；错误不泄漏
- **可验证性**：为每项修复提供命令/测试/HTTP 证据

## 成功度量

- 三个审计子代理（API契约/数据安全/UX文档）发现的问题全部进入修复清单
- 修复后：单测全绿、build 通过、E2E 全链路通过、文档逐项复核一致
- 独立 Critic 复验无未关闭的 BLOCKER/MAJOR

## 范围外

- 不引入账号价值评分/流式无效响应抑制（列为 P1 下批）
- 不做 CF Worker 部署改造（架构结论已在报告中）
- 不重写既有引擎核心
